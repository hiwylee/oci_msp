# 기획 에이전트 - 브레인스토밍 결과

## 1. 타겟 사용자 분석

### 주요 페르소나

#### Persona A: MSP 운영 엔지니어 (내부 사용자)
| 항목 | 내용 |
|------|------|
| 역할 | OCI 인프라 운영 및 고객사 지원 담당 |
| 기술 수준 | OCI 숙련자, CLI/Console 경험 풍부 |
| 주요 업무 | 다수 고객사 테넌시 동시 관리, 장애 대응, 변경 작업 |

**Pain Points**
- OCI Console을 고객사별로 로그인/로그아웃 반복 → 컨텍스트 스위칭 비용
- 다수 테넌시의 리소스 상태를 한눈에 파악하기 어려움
- 장애 발생 시 어느 고객사에서 알림이 왔는지 빠르게 식별 필요
- 반복 작업(서버 재기동, 스냅샷 생성 등)을 매번 수동으로 처리

**사용 시나리오**
1. 출근 후 전체 고객사 대시보드 확인 → 이상 징후 탐지
2. 특정 고객사 CPU 경보 수신 → 해당 테넌시로 즉시 이동
3. 스케일업 작업 수행 → 작업 내역 자동 기록
4. 일일 운영 리포트 자동 생성 및 고객사에 발송

---

#### Persona B: 고객사 IT 담당자 (외부 사용자)
**Pain Points**
- 현재 OCI에서 무슨 일이 일어나는지 실시간 파악 불가
- 비용이 왜 증가했는지 MSP에 물어봐야 알 수 있음
- 변경 작업에 대한 승인/거절 프로세스가 메일/전화로 진행됨

---

#### Persona C: MSP 서비스 관리자 / 운영 리더 (내부 사용자)
**Pain Points**
- SLA 준수 여부를 수동으로 집계해야 함
- 고객사별 수익성 분석이 어려움

## 2. 핵심 기능 목록

### MVP (Phase 1) - 필수 기능

| 기능 | 설명 |
|------|------|
| M1. 멀티 테넌시 관리 | 고객사 테넌시 등록/관리, 빠른 전환, 권한 분리 |
| M2. 통합 대시보드 | 전체 고객사 상태 요약, 주요 지표, 커스터마이즈 위젯 |
| M3. 리소스 관리 | Compute/Network/Storage/DB 조회 및 기본 제어 |
| M4. 모니터링 & 알림 | OCI Monitoring 연동, 알림 규칙, 이메일/Slack/SMS |
| M5. 작업 이력 관리 | 모든 작업 자동 기록, OCI Audit Log 연동 |
| M6. 사용자 및 권한 관리 | RBAC, MFA 지원 |

### Phase 2 - 중요 기능
- 고객 포털 (Customer Portal)
- 비용 관리 & 리포팅
- 서비스 요청 관리 (ITSM)
- 보안 관리
- 자동화 스케줄링

### Phase 3 - 차별화 기능
- AI 기반 이상 탐지 및 예측
- 자동 복구 (Auto-Remediation)
- 비용 최적화 엔진
- IaC 관리 (Terraform)
- 챗봇 (OCI GenAI 활용)

## 3. 비즈니스 모델

### 서비스 티어
| 티어 | 포함 서비스 |
|------|------------|
| Basic | 모니터링, 기본 대시보드, 이메일 알림 |
| Standard | Basic + SR 관리, 비용 리포팅, 고객 포털 |
| Premium | Standard + 자동화, AI 이상탐지 |
| Enterprise | Premium + SLA 보장, 커스텀 통합 |

### OCI 연결 방식 (권장: Cross-Tenancy IAM Policy)
- MSP 테넌시에서 고객 테넌시로 Cross-Tenancy 접근
- 고객사 측 승인 기반 연동
- API Key 방식도 지원 (하위 호환)

### RBAC 구조
```
Platform Admin → MSP Manager → Senior Engineer
                              → Engineer
                              → Junior Engineer
Customer Admin → Customer Viewer
```

### 위험도별 승인 워크플로우
| 위험도 | 처리 방식 |
|--------|----------|
| Low Risk | 자동 수행 |
| Medium Risk | 시니어 엔지니어 승인 |
| High Risk | 고객사 담당자 승인 |
| Critical | 고객사 + MSP 관리자 이중 승인 |
